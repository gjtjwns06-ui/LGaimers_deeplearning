# 데이터 이해 및 전처리 결과

이 문서는 요청한 범위인 **데이터 이해 → 전처리**까지만 다룬다. 데이터 분할, 검증 설계, 모델 설계, 학습, 검증, 튜닝, 앙상블·보정, 추론·제출은 진행하지 않았다.

## 1. 규칙에서 확정한 전처리 경계

- 평가 데이터의 각 행은 다른 평가 행에 의존하지 않고 처리해야 한다.
- 공식 `asof_*` 값은 현재 행의 투구 직전 정보이므로 사용할 수 있다.
- 평가 행끼리의 선수·팀·월별 집계, 빈도, rolling, expanding, 차분, 역방향 채움, target encoding은 금지된다.
- 현재 투구의 실제 결과·구종·TrackMan 값과 2025 TrackMan은 사용할 수 없다.
- 공개 `test.csv` 5행은 스키마 예시일 뿐이므로 행 수와 ID를 가정하지 않는다.
- `row_id`는 입력 순서를 보존하는 식별자로만 유지한다.

## 2. 데이터 규모와 품질

| 데이터 | 크기 | 관찰 |
| --- | ---: | --- |
| `train.csv` | 1,475,092 × 49 | 타깃 성공률 52.3766%, 2019~2024 |
| `test.csv` | 5 × 48 | 2025 스키마 샘플이며 분포 대표성 없음 |
| `trackman_history.csv` | 1,793,078 × 30 | 2019~2024, 내용 중복 2행·잘못된 카운트 문맥 98행 |

`train.csv`에는 `row_id` 중복, 전체 입력 중복, 상수 열, 무한대 값이 없다. TrackMan 물리량 결측률은 열별 약 0.42~0.70%다.

## 3. 그래프에서 확인한 숨은 패턴

### 시즌과 `game_type`의 구조적 단절

전체 성공률은 2019년 56.47%에서 2024년 48.61%로 7.86%p 하락했다. 가장 큰 변화는 `game_type=F`다. 2022년 70.87%에서 2023년 47.29%로 23.58%p 급락했다. 반면 `R`은 2019년 54.95%에서 2024년 48.97%로 완만하게 내려간다. 따라서 월 효과나 선수 이력의 전역 평균만 보면 이 체제 변화가 다른 신호처럼 보일 수 있다.

### 누적 성공률의 전역 관계는 체제 교란을 포함

전역 기준 투수 누적 성공률 하위·상위 10분위의 현재 성공률 차이는 15.55%p이고 최근 5경기 지표는 14.46%p다. 그러나 시즌과 경기유형을 함께 고정하면 `F` 내부의 투수 누적 성공률 상관은 시즌별 약 0.003~0.041로 크게 약해진다. 즉, 전역 단조 곡선의 일부는 선수 고유 신호가 아니라 시즌·경기유형 구성 차이다.

### 경기 문맥 신호

- 카운트별 최고는 0볼–1스트라이크 53.41%, 최저는 3볼–2스트라이크 49.96%다.
- 반대 손 조합은 53.26%, 같은 손 조합은 51.49%다.
- 1~3회는 53.10%, 9회 이상은 51.36%다.
- 주자·아웃 문맥 차이는 존재하지만 시즌×경기유형 단절보다 작다.

### 결측은 무작위가 아니다

- 최근 1/3/5경기 성공률·가운데 비율 6개는 정확히 같은 29,185행(1.9785%)에서 함께 비어 있다.
- 투수 핵심 누적률 결측 792행은 모두 `asof_pitcher_n=0`이다.
- 타자 누적률 결측 830행은 모두 `asof_batter_n=0`이다.
- 최근 경기 결측 행의 타깃 성공률은 55.08%, 관측 행은 52.32%다. 결측 자체가 데이터 생성 상태를 나타낸다.

### 선수 ID의 cold-start와 OOV

2024년 행 중 이전 시즌에 등장한 비율은 투수 80.14%, 타자 90.70%, 둘 다 등장한 행은 72.78%다. 딥러닝 입력에서 ID를 연속형 숫자로 처리하면 안 되며, 임베딩용 범주와 명시적 OOV가 필요하다.

### TrackMan의 별도 체제 변화

- 메인과 TrackMan의 투수·타자 ID 교집합은 모두 0이라 선수 단위 직접 조인이 불가능하다.
- fastball 비중은 2021년 57.46%에서 2022년 47.73%로 내려가고 breaking·offspeed가 증가한다.
- fastball 평균 `rel_speed`는 2021년 141.56에서 2022년 143.98로 계단식 상승하며 다른 주요 구종군도 함께 오른다. 장비·수집 체계 변화 가능성을 포함한 분포 단절로 취급해야 한다.
- 태그 구종명과 자동 구종명의 완전 일치율은 59.63%이고 표기 종류도 15개 대 10개다. 정규화된 `pitch_type_group`을 우선 사용한다.

### 시간 순서형 타깃 누수 함정

같은 선수의 다음 행 누적 성공률과 누적 횟수를 현재 행과 차분한 뒤 반올림하면 현재 타깃을 투수 1,474,300/1,474,300, 타자 1,474,262/1,474,262 전이에서 모두 복원한다. 따라서 미래 행 조회, 역방향 보간, 양방향 시퀀스 전처리, 평가 데이터 전체 선수 이력 집계는 금지한다.

## 4. 결정적 중복과 보존 기준

다음 관계를 전 행에서 확인했다.

- `run_total_before = run_top_before + run_bot_before`
- `score_diff_home = run_bot_before - run_top_before`
- `score_diff_pitcher_team`은 `top_bottom`에 따라 부호가 정해진 홈 점수 차
- `num_runners_on = runner_on_1b + runner_on_2b + runner_on_3b`
- `base_state`는 세 주자 플래그의 완전한 인코딩
- `asof_pitcher_pitchmix_n = asof_pitcher_n`
- 홈·원정 기대승률은 원본 반올림 오차 0.1 안에서 상보
- 세 pitch-mix 비율은 원본 반올림 오차 1e-6 안에서 합이 1

전처리 모듈은 이 관계를 먼저 검증한 뒤 아래 9개 열을 중복 표현으로 제거한다.

`run_total_before`, `score_diff_home`, 세 주자 플래그, `num_runners_on`, `away_win_expectancy`, `asof_pitcher_pitchmix_n`, `asof_pitcher_offspeed_rate`

`reverse/middle/ball/strike` 네 비율은 합이 1인 상호배타 구성값이 아니므로 정규화하거나 하나를 제거하지 않는다.

## 5. 구현된 전처리

`DeepTabularPreprocessor`는 다음만 수행한다.

1. 공식 스키마, 값 범위, 이진 타깃, 유한값, 결정적 관계를 검사한다.
2. 원본 프레임을 수정하지 않고 17개 범주형 열과 60개 수치형 열을 만든다.
3. ID·팀·손잡이·시즌·경기 문맥은 범주형 토큰으로 보존한다.
4. 범주형의 missing 인덱스 0과 OOV 인덱스 1을 분리한다.
5. `count_state`, `base_out_state`, `inning_bucket`, `platoon`, `score_state`를 현재 행에서만 만든다.
6. 월·요일 주기형, 점수·이력 횟수 `log1p`, count·주자 문맥을 현재 행에서만 만든다.
7. 15개 이력 비율의 원값과 결측 마스크를 함께 보존한다.
8. 호출자가 명시적으로 넘긴 참조 행에서만 범주 사전·수치 중앙값·평균·표준편차를 학습한다. 타깃은 모든 통계에서 제외한다.
9. `transform`은 상태를 갱신하지 않으며 한 행 단독 변환과 배치 안 변환 결과가 같다.

TrackMan 정제는 혼합 날짜 형식을 파싱하고, `Top/Bottom`을 `T/B`로 정규화하며, 내용 중복 2행과 잘못된 카운트 문맥 98행을 감사 가능하게 보고한다. 메인 선수 ID와 직접 연결하지 않고 독립 이력으로 유지한다.

- 재현 가능한 EDA: `scripts/run_data_understanding.py`

- 전처리 테스트: `tests/test_preprocessing.py`
- 전체 집계: `artifacts/data_understanding/summary.json`
- 그래프 원천 CSV와 11개 정적 그래프: `artifacts/data_understanding/`

전처리 단위 테스트 8개를 모두 통과했다. 전체 `train.csv` 1,475,092행은 청크 단위 스키마·결정 관계 검사를 통과했고, 공개 `test.csv` 5행은 범주형 5×17, 수치형 5×60으로 변환되며 모든 수치가 유한함을 확인했다.

여기서 작업을 종료한다. 이후 단계의 코드나 산출물은 이번 범위에서 생성하지 않았다.
